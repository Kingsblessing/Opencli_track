## 目标

把评论匹配从「命中关键词 = 客户」升级为 `algorithm.md` 主张的**潜在客户识别**：召回 → 方向消歧 → 帖子上下文 → 作者角色 → 去重 → 分级，输出 `lead_level` 可排序线索。纯规则实现，零新增依赖。

同时修掉两个实测确认的缺陷：
- `enrich_timestamps` 是空操作（`opencli xiaohongshu note` 不返回发布时间，字段匹配永不成立）；
- `keep_all=true` 时 `exclude_patterns` 失效（`match_comment` 返回 `[]`，与「未命中」不可区分）。

## 已确认决策

1. 纯规则 + 评分，不做 TF-IDF/embedding/LLM（`algorithm.md` §23 留作下一版）
2. 仅评论级判定，不提取发帖人线索（`post_type` 写入输出、参与加权）
3. `enrich_timestamps` → 重命名 `enrich_detail`，改为补详情数据（collects/comments/正文/标签）
4. CSV 默认输出全部评论 + `lead_level` 列

## 新增文件：`src/intent.py`（纯函数，可离线测试）

不含任何 opencli 调用，输入输出都是 `List[CommentItem]`，便于用 golden 用例锁死行为。

| 组件 | 职责 |
|---|---|
| `normalize(text)` | `[[^\]]{1,8}]` 去 B 站表情码、NFKC 全角归一、空白折叠、规避写法映射（`陪🥣/培🥣→陪玩`） |
| `IntentRules.from_config(match)` | 编译分组规则（正/负向、双向词、阈值） |
| `classify_post(title)` | 主贴分类：`service_selling`/`user_seeking`/`discussion`/`irrelevant` |
| `AuthorProfiler` | 按 `(platform, author_id)` 聚合（缺失时退回 `(platform, video_id, author)`），评论数 ≥ `min_comments` 才判定角色 |
| `Deduper` | 三级去重：归一化精确 / 同作者近似（`difflib.SequenceMatcher` ≥ 阈值）/ 跨作者刷屏标记 |
| `IntentEngine.run(comments, ctx)` | 编排上述步骤，**原地**写入判定字段，返回统计供日志 |

**方向消歧（核心）**：对 `接单/接陪/代打/代练/陪玩/技术` 这类双向词，先判方向再计分，卖家方向优先：
- 卖家向 `(我|本人|一直|目前|平时|长期|全天).{0,6}(接单|接陪|代打|代练|陪玩)` → `provider`，−5
- 买家向 `(现在|今天|还|有人|有没|能|可以).{0,4}(接单|接陪|代打)(吗|么|不)?` → `customer`，+4

**评分构成**：`Σ正向 + Σ负向 + 帖子上下文 + 作者角色`；`HIGH ≥6`、`MEDIUM 3~6`、`LOW 1~3`、`EXCLUDE <1 或卖家向主导`。权重表取自 `algorithm.md §15`：`order/availability +5`、`looking_for/price_query/skill_demand +4`、`game_demand +3`、`social_weak +1`、`topic_generic +0.5`（`陪`/`技术` 单独出现仅此低权重，不再构成判据）；`self_promo/recruitment −5`、`contact_solicit/pricing_offer/wait_order −4`、`voice_sales/teaching_offer −3`。

## 修改 `src/pipeline.py`

`step_comments` 从「边采边过滤」改为四段式（作者聚合与去重需要全量语料）：

1. **采集**：保持现有循环、`ctx.checkpoint()`、进度上报不变，但**不再过滤**，全量收进内存（量级 ~10³ 条）
2. **落原始语料**：始终写 `data/comments/raw_comments_<platform>_<stamp>.json`（未过滤，附 `post_type`）
3. **后处理**：`mode=intent` → `IntentEngine.run()`；`mode=keyword` → 走现有 `compile_patterns`/`match_comment`（并修 exclude 语义，用独立 `excluded` 标记）
4. **过滤与输出**：`keep_all`（默认全留）/ `only_leads` 二选一；`save_comment_outputs` 不变

新增 `--step match`：直接对最近一次 `raw_comments_*.json` 重跑判定，**不联网**——调规则时无需重爬，这是让 `algorithm.md` 的迭代方式可行的关键。

## 修改 `src/models.py`

`CommentItem` 追加（全部带默认值，现有按关键字构造不受影响）：
`positive_patterns` `negative_patterns` `intent` `intent_score` `lead_level` `reason` `post_type` `author_role` `author_comment_count` `author_seller_ratio` `dup_group` `dup_count` `is_representative`

`matched_patterns` 保留 = 正向命中，兼容旧下游。JSON 与 WebUI 预览是 schema 无关的（列取自 `rows[0].keys()`），新字段自动出现；**只有 CSV 需显式加列**。

## 修改 `src/platforms/redbook.py`

`enrich` → `enrich_detail`：调用 `opencli xiaohongshu note <url>`，把 `collects`/`comments` 并入 `stats`、`content`/`tags` 并入 `extra`（这些是搜索接口拿不到的）。删除永不命中的发布时间逻辑与 `_parse_exact_time`。`base.py` 同步改方法名与 `supports_enrich` 语义。

## 配置文件

`match` 改为分组结构，`mode` 决定走新算法还是旧行为（`mode: keyword` 时现有 `patterns` 照旧可用，升级可回退）：

```yaml
match:
  mode: intent              # intent(新) | keyword(旧行为)
  patterns: [...]           # mode=keyword 时使用,保留
  recall:   {order: {weight: 5, patterns: [...]}, availability: {...}, ...}
  negative: {self_promo: {weight: -5, patterns: [...]}, ...}
  direction:    {enabled: true}
  post_context: {enabled: true}
  author_role:  {enabled: true, min_comments: 2, seller_ratio: 0.6}
  dedup:        {enabled: true, similarity: 0.85, spam_min_authors: 3}
  thresholds:   {high: 6, medium: 3, low: 1}
  keep_all: true            # 依决策 4
  only_leads: false
```

顶部新增 `enrich_detail: false`（替换 `enrich_timestamps`）；`output.table_columns` 增补新字段。`config.yaml` 与 `config.test.yaml` 同步。

## WebUI

- `app.js`：新增 `match.mode` 下拉、阈值数值项、各阶段开关、`only_leads`；新增 `rules` 控件类型——按组渲染卡片（组名 / 权重 / 正则多行 / 删除），配「加组」按钮，保存时重建嵌套对象。

## 验证

1. **Golden 回归测试** `tests/test_intent.py`（stdlib `unittest`，venv 无 pytest）：以 `algorithm.md` 点名样例为核心断言 —— `怎么点`→customer/HIGH、`现在有人接吗`→customer/HIGH、`有没有技术女陪钻石`→customer/HIGH、`娱乐女陪20/h欢迎私信`→provider/EXCLUDE、`主页有战绩，可试音`→provider/EXCLUDE、`一起玩吗`→LOW、`陪玩接单很累`→irrelevant。约 50 条，锁死 intent 与 lead_level。
2. **离线调参闭环**：小规模重采一份语料（`data/` 已被清空，需重建）→ 反复 `--step match` 迭代规则，不联网。
3. **新旧对照**：同一 `raw_comments` 分别跑 `mode=keyword` 与 `mode=intent`，输出判定迁移矩阵，人工抽查误报修正比例；重点核对 `algorithm.md §1-2` 指出的两类问题（同行宣发被误判为客户、`怎么点`/`有人接吗` 漏检）。
4. **端到端**：WebUI 跑一次 all，确认新列出现在 CSV 与预览、`enrich_detail` 确实改动了 `stats`。
5. 顺带确认 `keep_all` 下 exclude 语义已修正。

## 风险与取舍

- **正则需真数据迭代**：种子规则来自 `algorithm.md` 的经验总结，阈值与词表必然要在真实语料上调，所以先把「离线重跑 + golden 用例」这套设施建起来，比一次写死正则更重要。
- **B 站无 `author_id`**：作者角色分析在小红书可靠（上游有 `userId`），B 站只能按昵称匹配，存在同名误合并。会在字段说明与 README 中写明，不假装精确。
- **`data/` 目前为空**：验证语料需重新采集，会以小规模（3~5 个帖子、`keep_all=true`）进行，保持限速。
- 暂不做：发帖人线索提取、ML/LLM 二阶段、跨运行评论去重（`dedup_across_runs` 仍只管采集步骤）。
